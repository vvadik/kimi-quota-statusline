## Дизайн

### 1. Публикация v1.1.1

В рабочем дереве имелись незакоммиченные, уже проверенные изменения:

- `statusline.py`: вместо фиксированного `kimi-code-cli/0.30.0` User-Agent официального API получает поле `version` из stdin-снимка и передаёт его из основного процесса в detached refresh; при отсутствии поля используется `kimi-code-cli`.
- Два пункта Unreleased в `CHANGELOG.md`: расход за весь день заменён расходом текущей сессии, а UA стал динамическим.
- `README.md` и языковая версия README: соответствующие синхронные изменения.

Порядок публикации (по разделу 6 MAINTAINING.md той версии):

1. Повторить ручной рендеринг и запрос официального API, подтвердив работоспособность рабочего дерева.
2. Изменить `kimi.plugin.json` version с `1.1.0` на `1.1.1`.
3. Перенести Unreleased в `## [1.1.1] - 2026-08-07` в CHANGELOG.
4. Выполнить `git add -A && git commit && git push`.
5. Создать и опубликовать tag `v1.1.1`.

### 2. Документирование проверки совместимости

В `docs/MAINTAINING.md` добавлен раздел «Проверка совместимости после обновления CLI» с уже проверенной последовательностью:

1. Прочитать официальный changelog и найти изменения status_line, manifest плагинов, wire-журналов и quota API.
2. Проверить поля stdin-снимка (`~/.kimi-code/statusline-stdin.json`): `model, cwd, gitBranch, permissionMode, planMode, maxContextTokens, sessionId, version`.
3. Проверить наличие `usage.record`, `thinkingEffort` и `swarm_mode` в `wire.jsonl` текущей сессии.
4. Выполнить `GET /coding/v1/usages` и подтвердить доступность официального quota API.
5. Проверить конфигурацию через `kimi doctor tui` и рендеринг через `cat ~/.kimi-code/statusline-stdin.json | python3 statusline.py`.
6. Если всё проходит, обновить только версионные сведения вроде UA; иначе найти неисправность по разделу о каналах данных в MAINTAINING.md.
